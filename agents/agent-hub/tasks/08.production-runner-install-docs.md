# 08. Production Runner Install Docs

## Deterministic Objective

This task is complete only when production installation documentation provides
copyable Codex hook and opencode plugin examples that call `agent-hub hook
notify`, documents trust and daemon startup requirements, and includes
doc-style validation that examples are syntactically present and point to the
documented Agent Hub CLI surface.

## Required Implementation

- Add production Codex hook examples for `SessionStart`, `UserPromptSubmit`,
  `Stop`, `PreToolUse`, and `PostToolUse`.
- Add production opencode plugin examples for `session.created`,
  `message.updated`, `session.idle`, `session.error`, `tool.execute.before`,
  and `tool.execute.after`.
- Explain Codex hook trust/review behavior.
- Explain local vs global opencode plugin installation.
- Explain that `agent-hubd` must be running before hooks are relied on.
- Keep integration tests based on fake runners, not production runner config.

## Required Doc-Style Test Tree

Create runnable doc-style tests under:

```text
agents/agent-hub/tests/08-production-runner-install-docs/
```

At minimum, include these 12 runnable leaves:

1. `codex-doc/session-start-example` verifies docs include `SessionStart` hook example.
2. `codex-doc/user-prompt-example` verifies docs include `UserPromptSubmit` example.
3. `codex-doc/stop-example` verifies docs include `Stop` example.
4. `codex-doc/pre-tool-example` verifies docs include `PreToolUse` example.
5. `codex-doc/post-tool-example` verifies docs include `PostToolUse` example.
6. `codex-doc/trust-warning` verifies docs explain Codex hook trust/review.
7. `opencode-doc/plugin-shape` verifies docs include an opencode plugin export.
8. `opencode-doc/session-created` verifies docs include `session.created` handling.
9. `opencode-doc/session-error` verifies docs include `session.error` handling.
10. `opencode-doc/tool-events` verifies docs include tool before/after handling.
11. `daemon-doc/start-required` verifies docs state `agent-hubd` must be running.
12. `test-doc/fakes-only` verifies docs state automated tests use fake runners.

Each leaf must have its own `SETUP.md` and `ASSERT.md`.

## Run Gate

After each documentation or code change, run:

```sh
go run ./agents/test-case-tree-runner test --rm agents/agent-hub/tests/08-production-runner-install-docs
```

If it fails, fix the docs, code, or doc-style tests and rerun the same command
until it passes. This is the final task gate.
